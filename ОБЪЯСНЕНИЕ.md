# Объяснение проекта Product App

## Что делает приложение

Это простой каталог товаров. Приложение загружает товары с сервера DummyJSON, показывает их списком и открывает страницу товара при нажатии. Для управления состоянием используется Bloc.

DummyJSON — готовый внешний сервер с тестовыми данными. Собственного сервера и базы данных в проекте нет. Приложение только читает данные: оно не добавляет и не изменяет товары.

## Как проходит загрузка

1. Функция `main()` запускает `MyApp`.
2. `MyApp` создаёт `ProductBloc` и отправляет ему событие `LoadProducts`.
3. Bloc показывает состояние `ProductsLoading` и вызывает `ProductApi.getProducts()`.
4. `ProductApi` через Dio отправляет GET-запрос к серверу и получает JSON.
5. `Product.fromJson()` превращает данные каждого товара в объект `Product`.
6. Если всё прошло успешно, Bloc выдаёт `ProductsLoaded` со списком. При ошибке — `ProductsError`.
7. `BlocBuilder` показывает загрузку, список или сообщение об ошибке с кнопкой повтора.
8. При нажатии на товар открывается `ProductPage` с уже загруженными данными. Повторный запрос для этой страницы не нужен.

## lib/main.dart

### main()

Точка входа в приложение. `runApp(const MyApp())` запускает главный виджет.

### MyApp

Главный виджет приложения. Наследуется от `StatelessWidget`: собственное изменяемое состояние в нём не хранится.

- `MyApp(...)` — конструктор виджета.
- `build(context)` — создаёт интерфейс. Внутри `BlocProvider` создаётся `ProductBloc` и ему отправляется `LoadProducts`. `MaterialApp` задаёт тему и первый экран `ProductsPage`.

### ProductsPage

Экран со списком товаров. Он тоже является `StatelessWidget`, а обновление экрана зависит от состояния Bloc.

- `ProductsPage(...)` — конструктор экрана.
- `build(context)` — создаёт страницу. Внутри `BlocBuilder` проверяется состояние Bloc: загрузка, ошибка или полученный список.
- `builder` внутри `BlocBuilder` — функция, которая получает текущее состояние и возвращает подходящий интерфейс.
- `itemBuilder` внутри `ListView.builder` — создаёт карточку для товара с нужным индексом.
- `onPressed` — при ошибке повторно отправляет событие `LoadProducts`.
- `onTap` — открывает `ProductPage` через `Navigator.push` и передаёт выбранный товар.
- `errorBuilder` у изображения — показывает значок, если картинка не загрузилась.

`builder`, `itemBuilder`, `onPressed`, `onTap` и `errorBuilder` здесь — функции обратного вызова, а не отдельные именованные методы класса.

## lib/product.dart

### Product

Модель товара — объект, в котором хранятся данные одного товара:

- `title` — название;
- `description` — описание;
- `price` — цена;
- `thumbnail` — адрес изображения.

- `Product(...)` — конструктор: создаёт товар из переданных значений. `required` означает, что эти значения нужно передать.
- `Product.fromJson(json)` — именованный `factory`-конструктор: берёт поля из JSON и создаёт `Product`. Цена преобразуется в `double`, потому что сервер может прислать число как целое или дробное.

## lib/product_api.dart

### ProductApi

Класс для получения товаров с сервера. Поле `dio` используется для HTTP-запроса.

- `getProducts()` — отправляет GET-запрос на `https://dummyjson.com/products`, берёт из ответа список `products`, циклом превращает каждый элемент в `Product` и возвращает список. Это асинхронный метод: `async` и `await` позволяют дождаться ответа сервера.

## lib/product_bloc.dart

### ProductEvent и LoadProducts

`ProductEvent` — общий тип событий Bloc. `LoadProducts` — событие «загрузить товары». Собственных методов у этих классов нет.

### ProductState и его состояния

`ProductState` — общий тип состояний. Собственных методов у него нет.

- `ProductsLoading` — идёт загрузка. Собственных методов нет.
- `ProductsLoaded` — товары загружены. Поле `products` хранит список. Конструктор `ProductsLoaded(this.products)` принимает этот список.
- `ProductsError` — при загрузке произошла ошибка. Собственных методов нет.

### ProductBloc

Связывает событие загрузки, запрос к серверу и состояния экрана. Наследуется от `Bloc<ProductEvent, ProductState>`.

- `ProductBloc(this.api)` — конструктор. Получает `ProductApi`, задаёт начальное состояние `ProductsLoading` и регистрирует обработчик события `LoadProducts`.
- Функция внутри `on<LoadProducts>(...)` обрабатывает событие: сначала выдаёт загрузку, затем вызывает `api.getProducts()`. В `try` при успехе выдаётся `ProductsLoaded`, а в `catch` при ошибке — `ProductsError`.
- `emit(...)` — метод Bloc для выдачи нового состояния; после этого `BlocBuilder` обновляет экран.

## lib/product_page.dart

### ProductPage

Экран подробной информации о товаре: изображение, название, цена и описание.

- `ProductPage(...)` — конструктор, принимает выбранный `product`.
- `build(context)` — создаёт экран с данными товара.
- `errorBuilder` у изображения показывает значок, если изображение не загрузилось.

## Что сказать на защите

«Это простой каталог товаров на Flutter. Приложение отправляет GET-запрос к открытому API DummyJSON через Dio и получает товары в формате JSON. Данные преобразуются в объекты Product. За состояние отвечает Bloc: он обрабатывает событие загрузки и выдаёт состояние загрузки, успеха или ошибки. Экран через BlocBuilder показывает нужное состояние. При нажатии на товар открывается страница с подробностями. Это одна кодовая база для разных платформ; я проверил веб-версию и Android, а iOS отдельно не проверял».

## Как запустить

```bash
flutter pub get
flutter run
```

На этом компьютере при зависании проверки обновлений Flutter можно запустить:

```bash
flutter --no-version-check pub get
flutter --no-version-check run
```

Для загрузки товаров нужен интернет.
